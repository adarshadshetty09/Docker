PostgreSQL to YugabyteDB Migration Guide

This guide will walk you through installing Docker on Ubuntu, setting up a PostgreSQL container, and then migrating a PostgreSQL database to YugabyteDB using the yb-voyager tool.

1. Install Docker and Set up PostgreSQL

First, let's install Docker on your Ubuntu system and get a PostgreSQL container up and running.

sudo apt-get update
sudo apt-get install docker.io -y
sudo usermod -aG docker $USER  # Replace with your system's username, e.g., 'ubuntu'
newgrp docker
sudo chmod 777 /var/run/docker.sock

Now, pull the PostgreSQL Docker image, create a Docker network, and start your PostgreSQL container:

docker pull postgres
docker network create my_network
docker run --name my_postgres --network my_network  -e POSTGRES_PASSWORD=mysecretpassword -p 5432:5432 -d postgres

2. Prepare the PostgreSQL Database

Next, we'll connect to your PostgreSQL container and set up a sample database and table within it.

docker exec -it my_postgres psql -U postgres

Once you are in the PostgreSQL prompt, run the following SQL commands:

CREATE DATABASE testdb;
\c testdb

CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100)
);

INSERT INTO users (name, email) VALUES

3. Download and Import Sample Data

We'll now download a larger sample dataset from Google Cloud Storage to simulate a real-world migration scenario.

First, authenticate with Google Cloud (if you haven't already):

gcloud auth login

Follow the prompts to complete the authentication in your browser. Then, copy the dataset to your local machine:

gsutil cp gs://yugabyteadarsha/postgres_air_2024.sql.zip .

Unzip the downloaded file and copy the SQL script into your PostgreSQL container:

unzip postgres_air_2024.sql.zip
docker cp postgres_air_2024.sql my_postgres:/postgres_air_2024.sql

Now, execute the SQL script inside the PostgreSQL container to import this large dataset:

docker exec -it my_postgres bash
psql -U postgres -d testdb -f /postgres_air_2024.sql

After the import, you can inspect the newly imported schema and tables:

\c testdb
\dn
\dt

Finally, drop the postgres_air schema to prepare for the migration process with yb-voyager:

DROP SCHEMA postgres_air CASCADE;

4. Build and Run YugabyteDB Docker Image

We'll create a Dockerfile to build a YugabyteDB image that includes yb-voyager.

FROM rockylinux:9

ENV YB_VERSION=2.25.1.0 \
    YB_BUILD=b381 \
    YB_PLATFORM=linux-x86_64 \
    OIC_URL="https://download.oracle.com/otn_software/linux/instantclient/215000"

# Install dependencies
RUN dnf install -y wget tar hostname procps glibc-langpack-en \
    && dnf clean all

# Download and extract YugabyteDB
RUN wget https://software.yugabyte.com/releases/${YB_VERSION}/yugabyte-${YB_VERSION}-${YB_BUILD}-${YB_PLATFORM}.tar.gz \
    && tar -xvzf yugabyte-${YB_VERSION}-${YB_BUILD}-${YB_PLATFORM}.tar.gz \
    && rm -f yugabyte-${YB_VERSION}-${YB_BUILD}-${YB_PLATFORM}.tar.gz

# Set working directory
WORKDIR /yugabyte-${YB_VERSION}

# Run post-install script
RUN ./bin/post_install.sh

RUN dnf update -y \
    && dnf install https://downloads.yugabyte.com/repos/reporpms/yb-yum-repo-1.1-0.noarch.rpm -y \
    && dnf install https://dl.fedoraproject.org/pub/epel/epel-release-latest-9.noarch.rpm -y \
    && dnf install https://dev.mysql.com/get/mysql84-community-release-el9-1.noarch.rpm -y \
    && dnf --disablerepo=* install https://download.postgresql.org/pub/repos/yum/reporpms/EL-9-x86_64/pgdg-redhat-repo-latest.noarch.rpm -y \
    && dnf -qy module disable postgresql \
    && dnf install perl-open.noarch -y \
    && dnf install -y \
           ${OIC_URL}/oracle-instantclient-tools-21.5.0.0.0-1.x86_64.rpm \
           ${OIC_URL}/oracle-instantclient-basic-21.5.0.0.0-1.x86_64.rpm \
           ${OIC_URL}/oracle-instantclient-devel-21.5.0.0.0-1.x86_64.rpm \
           ${OIC_URL}/oracle-instantclient-jdbc-21.5.0.0.0-1.x86_64.rpm \
           ${OIC_URL}/oracle-instantclient-sqlplus-21.5.0.0.0-1.x86_64.rpm \
    && dnf update -y \
    && dnf install yb-voyager -y

RUN yb-voyager version

# Expose port
EXPOSE 15433 7000 9000 9042 5433 6379 6380 11000

# Start YugabyteDB (no --docker flag)
CMD ["./bin/yugabyted", "start", "--daemon=false"]

Build the Docker image using the Dockerfile:

docker build -f Dockerfile -t yugabyte-rocky:2.25.1 .

Create a directory for YugabyteDB data and set the appropriate permissions:

sudo mkdir -p /opt/yugabyte_data
sudo chown -R $(whoami):$(whoami) /opt/yugabyte_data

Now, run the YugabyteDB container, mounting the data directory and connecting it to the same network as your PostgreSQL container:

docker run -d --name yugabyte \
  --network my_network \
  -v /opt/yugabyte_data:/root/var/data \
  -e CONTROL_PLANE_TYPE=yugabyted \
  -e YUGABYTED_DB_CONN_STRING="postgresql://yugabyte:yugabyte@yugabyte:5433" \
  -p 7000:7000 \
  -p 9000:9000 \
  -p 15433:15433 \
  -p 5433:5433 \
  -p 9042:9042 \
  yugabyte-rocky:2.25.1 \
  ./bin/yugabyted start --background=false

5. Configure YugabyteDB for Migration

Connect to your running YugabyteDB container to set up a ybvoyager user and a target database.

docker exec -it <YUGABYTE_CONTAINER_ID> bash # Replace <YUGABYTE_CONTAINER_ID> with the actual ID
psql -U postgres

Once inside the YugabyteDB psql prompt, execute these commands:

CREATE USER ybvoyager PASSWORD 'password';
GRANT USAGE ON SCHEMA public TO ybvoyager;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO ybvoyager;
ALTER USER postgres WITH PASSWORD 'password';

Now, create the target database in YugabyteDB with colocation enabled:

./bin/ysqlsh -h <YUGABYTE_CONTAINER_IP> -U yugabyte -d yugabyte # Replace with container IP
CREATE DATABASE target_db_name WITH COLOCATION=true;
CREATE USER ybvoyager SUPERUSER PASSWORD 'password';

6. Grant Permissions for yb-voyager

Run the yb-voyager-pg-grant-migration-permissions.sql script on your source PostgreSQL database to grant the necessary permissions to the ybvoyager user for migration.

psql -h my_postgres \
     -d testdb \
     -U postgres \
     -v voyager_user='ybvoyager' \
     -v schema_list='postgres_air' \
     -v is_live_migration=0 \
     -v is_live_migration_fall_back=0 \
     -f /opt/yb-voyager/guardrails-scripts/yb-voyager-pg-grant-migration-permissions.sql

Note: When prompted, enter the password for the postgres user (which is mysecretpassword).

7. Perform the Migration with yb-voyager

First, create a directory to store your yb-voyager export files:

mkdir $HOME/export-dir
export EXPORT_DIR=$HOME/export-dir

Assess Migration

Assess the migration readiness of your PostgreSQL database for YugabyteDB:

yb-voyager assess-migration --source-db-type postgresql \
    --source-db-host my_postgres --source-db-user ybvoyager \
    --source-db-password password --source-db-name testdb \
    --source-db-schema postgres_air --export-dir /root/export-dir

Note: When prompted, type Y to continue with the latest stable YugabyteDB version and Y again to continue despite any warnings regarding pg_stat_statements and IOPS.

Export Schema

Export the schema from your PostgreSQL database:

yb-voyager export schema \
  --export-dir /root/export-dir \
  --source-db-type postgresql \
  --source-db-host my_postgres \
  --source-db-user ybvoyager \
  --source-db-password password \
  --source-db-name testdb \
  --source-db-schema postgres_air \
  --start-clean true

Analyze Schema

Analyze the exported schema to ensure compatibility with YugabyteDB:

yb-voyager analyze-schema --export-dir /root/export-dir --output-format txt

Note: Type Y when prompted to continue with the latest stable YugabyteDB version.

Import Schema

Import the schema into your YugabyteDB cluster:

yb-voyager import schema \
  --export-dir /root/export-dir \
  --target-db-host yugabyte \
  --target-db-user yugabyte \
  --target-db-password yugabyte \
  --target-db-name target_db_name

Export Data

Export the data from your PostgreSQL database:

yb-voyager export data \
  --export-dir /root/export-dir \
  --source-db-type postgresql \
  --source-db-host my_postgres \
  --source-db-user ybvoyager \
  --source-db-password password \
  --source-db-name testdb \
  --source-db-schema postgres_air

Check Export Data Status

Verify the status of your data export:

yb-voyager export data status --export-dir /root/export-dir

Import Data

Import the exported data into your YugabyteDB cluster:

yb-voyager import data \
  --export-dir /root/export-dir \
  --target-db-host yugabyte \
  --target-db-user yugabyte \
  --target-db-password yugabyte \
  --target-db-name target_db_name \
  --parallel-jobs 4 \
  --enable-adaptive-parallelism false \
  --batch-size 20000

8. Finalize Migration and Clean Up

After the data import is complete, finalize the schema in YugabyteDB.

Finalize Schema

yb-voyager finalize-schema-post-data-import \
  --export-dir /root/export-dir \
  --target-db-host yugabyte \
  --target-db-user yugabyte \
  --target-db-password yugabyte \
  --target-db-name target_db_name

End Migration

To clean up migration artifacts and save migration reports, first create a backup directory:

mkdir /root/backup-dir

Then, end the migration, ensuring all necessary files are backed up:

yb-voyager end migration --export-dir /root/export-dir \
  --backup-log-files true \
  --backup-data-files true \
  --backup-schema-files true \
  --save-migration-reports true \
  --backup-dir /root/backup-dir

Clean Up ybvoyager User and Schema in PostgreSQL

Finally, clean up the ybvoyager user and any related objects from your source PostgreSQL database. You'll need to connect to the testdb database in your my_postgres container:

docker exec -it my_postgres psql -U postgres -d testdb

Inside the PostgreSQL prompt, run these commands to remove the user and schema created for the migration:

REASSIGN OWNED BY ybvoyager TO postgres;
DROP OWNED BY ybvoyager;
DROP USER ybvoyager;
DROP SCHEMA postgres_air CASCADE;

You have successfully migrated your PostgreSQL database to YugabyteDB! Do you have any further questions about migrating databases or working with YugabyteDB?
